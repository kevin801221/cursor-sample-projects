現代 Chrome 擴充功能安全架構與 Manifest V3 演進

發佈於 2026 年 · 科技架構特刊

在過去 Manifest V2 時代，許多擴充功能開發者習慣將 OpenAI 或雲端服務的 API Key 直接寫死在 Content Script 中。這種做法存在極大的資安隱患——因為 Content Script 運行在目標網頁的 DOM 環境中，惡意網站只需透過簡單的 JavaScript 注入或 DOM 遍歷，就能輕易竊取使用者的私密金鑰。

Manifest V3 的核心精神是「環境隔離與最小權限原則」。我們將擴充功能拆解為三個角色：派往外部網頁的「實習生」Content Script、駐守本機保險箱的「總管」Service Worker，以及隨身攜帶的「對講機」Popup 面板。實習生只負責監聽選字動作，當需要進行 AI 摘要或翻譯時，透過 chrome.runtime.sendMessage 將文字送交總管。

總管在獨立且受信任的 Service Worker 環境中，從 chrome.storage 安全讀取金鑰，代理發送 HTTPS 請求至 LLM 模型 API，最後將乾淨的摘要結果回傳給實習生呈現。透過此架構，金鑰永遠不會暴露給任何第三方網頁。
