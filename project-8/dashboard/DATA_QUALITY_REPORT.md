# 資料品質報告（探索階段的產出）

> 這份是 walkthrough 第 3 節「Ask Mode 探索式分析」的成果範例。
> 重點不是報告本身，而是**先看清楚問題再決定怎麼清**——底下每一條發現，
> 都對應 `pipeline.py` 裡的一個清理步驟。
>
> 自己重跑一次：`uv run python pipeline.py --report`

## customers_raw.csv（500 列 × 5 欄）

| 欄位 | 型別 | 缺失值 | 缺失率 | 相異值 |
|---|---|---|---|---|
| id | int64 | 0 | 0.0% | 490 |
| email | str | 150 | 30.0% | 342 |
| signup_date | str | 0 | 0.0% | 381 |
| plan | str | 0 | 0.0% | 12 |
| region | str | 0 | 0.0% | 31 |

- 完全重複列：**10 列**
- `id` 只有 490 個相異值（500 列裡有 10 列是別人的複製品）
- `plan` 有 **12 種**寫法，但方案其實只有 3 種（`PRO`、`Pro`、` pro ` 都是同一個）
- `region` 有 **31 種**寫法，但地區其實只有 5 個（`Taipei`、`臺北`、`台北市`、` 台北 `）
- `signup_date` 混了三種格式：`2024-03-05`、`2024/03/05`、`2024年03月05日`

## transactions_raw.csv（2000 列 × 4 欄）

| 欄位 | 型別 | 缺失值 | 缺失率 | 相異值 |
|---|---|---|---|---|
| customer_id | int64 | 0 | 0.0% | 365 |
| transaction_date | str | 0 | 0.0% | 581 |
| amount | str | 10 | 0.5% | 674 |
| region | str | 0 | 0.0% | 31 |

- `amount` **不是數字欄位**，是字串欄位——裡面混進了 `NT$380`、`1,250`、`待確認`
- `amount` 無法轉成數字：**65 列**
- `amount` 負值：**200 列（10.0%）**
- `amount` 統計：min=-573、max=4976、mean=443.7、std=925.9
- `amount` 離群值（IQR 法，> 1152）：**173 列**
- 完全重複列：**15 列**
- `customer_id` 在客戶主表查無此人：**121 列（6.0%）**

## 決策（看完報告才做的決定）

| 發現 | 決定 | 為什麼 |
|---|---|---|
| email 缺 30% | **不刪，填 `unknown@company.com`** | 刪掉等於丟掉三分之一的客戶；缺 email 不代表這個客戶不存在 |
| plan / region 大小寫與別名 | 標準化收斂 | 不收斂的話「台北」會被拆成 6 個地區，圖表全錯 |
| 日期三種格式 | 先字串正規化再 `to_datetime` | 直接 `to_datetime` 會把中文日期變成 NaT，靜靜吃掉資料 |
| amount 混字串 | 先洗 `NT$` 與逗號救回來，剩下的 `to_numeric(errors='coerce')` 丟掉 | 救得回來的錢不要丟；救不回來的要記帳 |
| amount 負值 200 列 | 刪除，但**印出金額合計** | 這些可能是退款也可能是誤輸入，刪之前要讓業務看到金額 |
| 孤立 customer_id 121 列 | 刪除 | 交易對不到客戶，任何 per-customer 指標都會算錯 |
| 離群值 173 列 | **不刪，只標記** | 離群值裡是最大的客戶，刪掉等於把營收從報表上抹掉 |
